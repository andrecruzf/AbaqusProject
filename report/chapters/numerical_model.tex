\chapter{Automated Numerical Framework}\label{chap:numerical_model}

\section{Framework Overview}

To complement the experimental campaign presented in
Chapter~\ref{chap:experimental_campaign}, a numerical simulation framework was
developed in Abaqus/Explicit. Its purpose is to create, run, and post-process
the specimen and punch configurations considered in Task~I in a reproducible
way. The framework is not written for one single model, but for repeated
simulation campaigns in which the test type, geometry, mesh density, material
orientation, loading, and post-processing settings can be changed from a common
interface.

The main design goal was automation. Starting from a central configuration
file, the pipeline builds the finite element model, writes the Abaqus input
deck, submits the simulation, extracts the relevant quantities from the output
database, and stores the processed results in a common format. This makes it
possible to compare Nakazima, Marciniak, and Punch-in-Punch simulations using
the same numerical and post-processing workflow.

Special attention was paid to the mesh. Since the numerical results should be
compared across different specimen and punch configurations, the element size
must be controlled systematically. The framework therefore includes
user-defined mesh-size modification routines, which allow mesh-refinement
studies to be generated automatically instead of manually rebuilding each
model.

\section{Framework Architecture}
\subsection{Central Configuration}

The framework is controlled through a central configuration file, which acts as
the user interface of the numerical model. It defines the selected test
configuration, specimen dimensions, punch setup, mesh controls, material
orientation, contact parameters, loading conditions, solver settings, and
post-processing options. Parameters that are expected to change between
campaigns are exposed there, while the implementation of the model-building
steps remains fixed.

This separation reduces the risk of introducing unintended differences between
simulation cases. For example, a change in sheet thickness, punch diameter, or
mesh refinement factor does not require editing the Abaqus model manually. The
complete list of available configuration groups is given in
Appendix~\ref{app:configuration_parameters}.

\subsection{Automated Workflow}

The model generation is organised as a sequence of Python modules. The main
script first reads the configuration and then creates the specimen, tools,
assembly, material definition, analysis step, contact interactions, boundary
conditions, output requests, and job definition. Each simulation therefore
passes through the same sequence of operations, independent of the selected
test type.

After the model has been generated, the input file and the user material
subroutine are placed in the simulation directory. Once the Abaqus/Explicit job
has finished, the same post-processing script reads the output database (ODB)
and writes the force-displacement data, energy histories, strain paths, and
forming-limit points. The resulting file structure is kept identical for all
test configurations so that the results can be aggregated without additional
manual work.

\subsection{Integration with the ETH Euler Cluster}

The simulations are executed on the ETH Euler cluster. The local project files
are copied to the cluster. The solver job is then submitted through SLURM,
and the ODB post-processing is performed after the analysis has completed.

Only the compact result files, figures, and movies are copied back to the
project directory. The large ODB files remain in scratch storage due to Euler directories storage policies. 

\section{Automated Model Generation}

\subsection{Test Configurations}

Three test configurations are supported. The Nakazima model represents the
standard hemispherical-punch test and is used as the main reference
configuration. The Marciniak model uses a flat punch and provides a second
forming setup with a different strain-path character. The Punch-in-Punch model
contains an outer and an inner punch and is used to study a two-stage forming
process.

All three configurations are generated by the same framework. Differences such
as the number of punches, tool geometry, contact pairs, and loading sequence
are selected through the configuration file. 

\subsection{Geometry, Contact and Boundary Conditions}

To reduce the computational cost, only one quarter of the specimen is
modelled. Symmetry boundary conditions are applied on the two cut planes,
while all tooling components are represented as analytical rigid bodies. The
forming motion is prescribed through the punch reference point, whereas the die
and blank holder remain fixed. The outer blank edge is constrained to
represent the clamping action of the experimental setup.

Tool--blank interactions are modelled using hard normal contact with Coulomb
friction. The same contact formulation is employed for the Nakazima and
Marciniak configurations, while the Punch-in-Punch model activates the
additional contact interactions associated with the second punch. Consequently,
the overall modelling strategy remains identical across the three test
configurations, with only the geometry and loading sequence being adapted.

\subsection{Parameterized Mesh Generation}

The deformable sheet is discretised using eight-node linear
reduced-integration hexahedral elements (\texttt{C3D8R}). A solid formulation
is adopted because the constitutive model accounts for through-thickness
deformation, damage evolution, and element deletion.

The mesh is generated from a parameterized partitioning strategy, illustrated
in Figure~\ref{fig:bm_mesh_zones}. The specimen is divided into a series of
partitioned regions that establish a consistent mesh topology across the
different specimen geometries. Selected radial and circumferential partition
lines are used as independent seeding controls, allowing the mesh density to be
adjusted locally while preserving the overall mesh structure.

Two levels of mesh control are available. For routine simulations and
mesh-convergence studies, a global refinement factor uniformly scales the
target seed spacing while preserving the underlying topology. For more advanced
applications, the radial and circumferential seeding can be adjusted
independently along the partition lines, enabling local refinement or
coarsening in selected regions while maintaining mesh compatibility throughout
the specimen.
\section{Numerical Formulation}

\subsection{Material Model}

The sheet material is described through a user material subroutine (VUMAT). The
constitutive formulation combines a Hill48 anisotropic yield criterion, mixed
Swift--Voce isotropic hardening, and a Hosford--Coulomb damage model for
fracture initiation. This combination provides a unified description of the
plastic response, strain hardening, and fracture behaviour required for the
forming-limit simulations.

The material orientation is defined through a local material coordinate system,
whose rolling direction can be specified in the Master configuration. This
allows rolling- and transverse-direction simulations to be performed using the
same numerical model without modifying the underlying implementation.

Material degradation and fracture are represented through the internal damage
variables of the VUMAT, which trigger element deletion upon failure. Besides
representing crack initiation, the resulting deletion pattern is used during
post-processing to identify the fracture location and distinguish valid
dome-centred fractures from failures occurring outside the evaluation region.

\subsection{Quasi-Static Solution Strategy}

Although the experimental forming tests are quasi-static, the numerical
simulations are performed using Abaqus/Explicit. Maintaining a quasi-static
response therefore requires limiting the inertial effects introduced by the
explicit solution procedure while keeping the computational cost within
reasonable limits.

The numerical behaviour is governed by three coupled parameters: the punch
velocity, the mesh discretization, and the applied mass scaling. A finer mesh
reduces the stable time increment, increasing the computational cost, whereas
higher punch velocities or more aggressive mass scaling improve computational
efficiency at the expense of increased inertial effects. Consequently, these
parameters must be selected jointly to obtain an efficient simulation while
preserving a quasi-static response.

To verify the validity of each simulation, the kinetic and internal energy
histories are extracted automatically during post-processing. The ratio of
kinetic to internal energy ($\mathrm{ALLKE}/\mathrm{ALLIE}$) is then evaluated
to quantify the influence of inertia. Together with the mesh and mass-scaling
sensitivity studies presented in Chapter~\ref{chap:results}, this provides the
basis for selecting numerical parameters that remain representative of the
physical quasi-static experiment.

\section{Automated Post-Processing and Forming-Limit Extraction}

Following each simulation, the output database (ODB) is processed
automatically through a common post-processing pipeline. The extracted
quantities serve two complementary purposes: validating the numerical
simulation and generating the data required for forming-limit
identification.

To assess the quality and consistency of the simulation, the pipeline extracts
the punch force--displacement response, the kinetic and internal energy
histories, and a series of diagnostic visualizations, including section and
isometric view animations together with representative mesh-topology snapshots.
These outputs allow the quasi-static assumption, deformation evolution, and
overall simulation behaviour to be verified without manual inspection of the
ODB.

For forming-limit identification, element-based quantities are extracted
throughout the simulation, including strain histories, damage variables, and
element status information. These data are used to detect crack initiation,
identify the fracture location, and extract the critical strain state from the
evaluation region. When requested, the same dataset is further processed to
evaluate necking indicators based on the Volk--Hora methodology and on the
damage evolution predicted by the constitutive model.

This automated post-processing stage converts the raw finite element results
into a standardized set of numerical outputs that mirrors the experimental
evaluation procedure. Consequently, both numerical and experimental forming
limits are obtained in a common format, enabling a direct comparison in
Chapter~\ref{chap:results}.

\chapter{Numerical Model}\label{chap:numerical_model}

\section{Model Overview}

The numerical framework replicates the forming tests required by Task~I in Abaqus/Explicit. The selected test is chosen via the \texttt{TEST\_TYPE} flag (\texttt{nakazima}, \texttt{marciniak}, or \texttt{pip}) in the central configuration file. Due to two planes of symmetry, only a quarter of the specimen is modelled, significantly reducing computational cost.

Table~\ref{tab:tool_geometry} summarises the tool geometry for each test configuration.

For the PiP configuration, the model includes five parts:
\begin{itemize}
  \item \textbf{Blank}: deformable solid, meshed with the reference specimen geometry.
  \item \textbf{Punch~1}: annular rigid body (inner bore $r = 20$\,mm, outer $r = 43.75$\,mm).
  \item \textbf{Punch~2}: inner hemispherical rigid body ($R = 15$\,mm).
  \item \textbf{Die}: rigid ring with flat contact face and 15\,mm fillet.
  \item \textbf{Blank holder}: rigid body with 2\,mm inner chamfer, inner radius 62.5\,mm.
\end{itemize}

For Nakazima and Marciniak, the standard four-part model is used (single punch, die, blank holder, blank). Specimen geometry files (\texttt{.cae}) are provided for widths $W \in \{20, 50, 80, 90, 100, 120, 200\}$\,mm and are shared between all test configurations. The workflow is parameterised such that sheet thickness, material orientation, punch travel, forming speed, mass scaling, and mesh refinement can be changed without editing the model-building scripts.

\section{Discretisation}

The blank is meshed with eight-node linear brick elements with reduced integration and hourglass control (\texttt{C3D8R}). A single element layer is used through the thickness, consistent with the reference geometry files and with the mesh configuration used in the reference model (PinP\_CR210H). The relevant mesh metric for this project is the element size in the dome and contact zone, because this is where strain localisation is evaluated.

Maintaining a consistent element size across all specimen widths and test configurations is a primary requirement of the project outline. The model-building workflow therefore treats mesh size as a controlled parameter rather than as an incidental property of each imported geometry. A user-defined mesh-refinement factor is applied during model generation, allowing the same target element length to be imposed across widths, sheet thicknesses, and punch configurations. This prevents apparent differences in forming limits from being caused by different spatial resolutions.

The automated mesh-size modification also enables the Task~III mesh study. Instead of manually preparing separate geometry files, the same build script generates a controlled set of meshes and post-processes them with identical criteria. The resulting convergence data are used to select the production mesh density for the full parametric campaign.

\section{Material Model}

The blank material is defined via a VUMAT Fortran subroutine (\texttt{VUMAT\_explicit.f}), which implements the Hosford-Coulomb criterion with 46 material constants. The subroutine computes the stress update using a radial return algorithm and evaluates the fracture criterion at each increment. Initial conditions for SDV8 ($\beta = 1.0$) and SDV17 ($\bar{\varepsilon}^p_f$) are injected programmatically at the start of the step to work around an Abaqus 2023 CAE limitation with VUMAT predefined fields.

\section{Boundary Conditions and Interactions}

Symmetry boundary conditions are applied on the two cut planes of the quarter model. The blank holder and die are fully fixed. Surface-to-surface kinematic contact is defined between the blank and each rigid tool, with Coulomb friction coefficients set in \texttt{config.py}.

For the PiP configuration, the two-step process is controlled by separate boundary conditions on each punch reference point:
\begin{itemize}
  \item \textbf{Step~1} (\texttt{Step1\_Clamp}, 10\,s): both Punch~1 and Punch~2 advance 20\,mm together with a linear amplitude.
  \item \textbf{Step~2} (\texttt{Step2\_Form}, 10\,s): Punch~1 is locked via an \texttt{EncastreBC} (zero nodal velocity, holding at end-of-step-1 position); Punch~2 advances a further 20\,mm with a linear amplitude.
\end{itemize}

For Nakazima and Marciniak, a single \texttt{Forming} step (10\,s) uses a smooth-step amplitude to prescribe the 50\,mm punch displacement.

\section{Forming Speed and Mass Scaling}

All simulations use a punch speed of 5\,mm/s. This is an artificial speed used in the quasi-static Abaqus/Explicit framework: the step time is set to $t = d/v$ (10\,s for Nakazima/Marciniak; $2 \times 10$\,s for PiP).

Fixed mass scaling with a target stable time increment $\Delta t = 1 \times 10^{-5}$\,s is applied to maintain computational efficiency. The quasi-static assumption is validated post-hoc by verifying that the ratio of kinetic to internal energy (ALLKE/ALLIE) remains below 5\% throughout the simulation.

\subsection{Mass Scaling Sensitivity Study}\label{sec:mass_scaling_study}

Mass scaling introduces artificial mass to increase the stable time increment $\Delta t$, reducing the number of explicit increments and therefore the wall-clock time. The added mass inflates the kinetic energy, so the quasi-static assumption becomes less valid as $\Delta t$ grows: $\mathrm{ALLKE} \propto \dot{u}^2 \Delta m \propto \Delta t^2$, meaning a ten-fold increase in $\Delta t$ raises the kinetic-to-internal energy ratio by roughly two orders of magnitude.

To identify the largest $\Delta t$ that keeps the simulation quasi-static, a dedicated one-dimensional sweep was conducted on a representative W200 specimen ($t = 1.5$\,mm) using four values:
\[
  \Delta t \in \{1\times10^{-7},\; 1\times10^{-6},\; 1\times10^{-5},\; 1\times10^{-4}\}\,\text{s}.
\]
The quality metric is the mean ALLKE/ALLIE ratio evaluated over the second half of the simulation time, which avoids the transient spike that occurs at initial punch contact. The 5\,\% quasi-static threshold from the Abaqus documentation~\cite{AbaqusManual} is used as the acceptance criterion. Results are presented in Section~\ref{sec:study_mass_scaling}.

\subsection{Mesh Refinement Study}\label{sec:mesh_refinement_study}

Element size directly controls the accuracy with which strain gradients in the dome zone are resolved, and hence the reliability of the extracted FLC point. A mesh that is too coarse smears the localised neck over several elements, underestimating the peak major strain $\varepsilon_1$ at failure. Conversely, very fine meshes increase runtime significantly and can make full FLC campaigns computationally prohibitive. The mesh study is therefore part of the framework design, not a separate manual validation exercise.

The mesh refinement factor $f_\mathrm{MR}$ scales the target element size relative to the reference geometry. Three levels were studied:
\[
  f_\mathrm{MR} \in \{1,\; 2,\; 4\},
\]
where $f_\mathrm{MR} = 1$ corresponds to the coarsest mesh and $f_\mathrm{MR} = 4$ to the finest. The deviation of the extracted major failure strain from the reference value (finest mesh, smallest $\Delta t$) is used as the convergence metric:
\[
  \Delta\varepsilon_1 = \frac{\varepsilon_1(f_\mathrm{MR},\,\Delta t) - \varepsilon_1^\mathrm{ref}}{\varepsilon_1^\mathrm{ref}} \times 100\,\%.
\]
Results are presented in Section~\ref{sec:study_mesh}.

\subsection{Combined Parameter Study}\label{sec:combined_study}

The mass scaling and mesh refinement studies were executed simultaneously as a fully factorial $4 \times 3$ grid (12 simulations total) on the W200 Nakazima specimen. Running both axes together reveals interactions between the two parameters: for coarser meshes the element-level stable time increment is inherently larger, so the same mass scaling $\Delta t$ produces a different ratio of artificial to natural mass. The combined study therefore provides a more realistic basis for parameter selection than independent one-at-a-time sweeps.

The grid was deployed via \texttt{deploy\_study.sh}, which pushes all scripts once via \texttt{rsync --checksum} and calls \texttt{submit\_one.sh} once per combination via blocking SSH, collecting the SLURM job IDs to wire a downstream \texttt{plot\_study.py} aggregation job with an \texttt{afterok} dependency. The aggregation produces a three-panel heatmap (wall time, mean ALLKE/ALLIE, $\Delta\varepsilon_1$) that simultaneously visualises all trade-offs. Results are presented in Section~\ref{sec:study_combined}.

\section{Output Requests}

Field outputs are requested at regular intervals and include:
\begin{itemize}
  \item \texttt{LE}: Logarithmic strain tensor (used to compute principal strains $\varepsilon_1$, $\varepsilon_2$).
  \item \texttt{SDV1--17}: All solution-dependent variables (EQPS, stress state, fracture strain).
  \item \texttt{STATUS}: Element status (0 = deleted, used to detect failure frame).
  \item \texttt{S}, \texttt{U}, \texttt{RF}: Stress, displacement, reaction forces.
\end{itemize}

History output includes whole-model energies \texttt{ALLKE} and \texttt{ALLIE} for quasi-static validation.

\section{Simulation Pipeline}

The entire workflow is automated via a set of Python and shell scripts deployed on the ETH Euler HPC cluster. It follows three stages: model creation, solver execution, and post-processing. The pipeline runs end-to-end from a single deployment command on the local machine, which pushes all scripts to the cluster, builds Abaqus models for all specimen widths, submits the corresponding solver jobs, and queues a downstream FLC aggregation job with a SLURM dependency.

Model building is handled by a central orchestrator script that calls eight modules sequentially (parts, assembly, material, step, contact, boundary, output, job) and writes the solver input file. After the explicit solver completes on the compute node, an ODB-based post-processing script extracts principal strains, equivalent plastic strain, damage, and energy histories into structured CSV files. A plotting script generates per-specimen diagnostic figures, and a final aggregation step combines all forming-limit points into a single FLC diagram.

The full repository structure, file descriptions, and execution commands are provided in Appendix~\ref{app:pipeline}.

\section{Failure and Necking Detection}

Four independent criteria are implemented in \texttt{postproc.py} to extract a forming-limit point from each simulation, written as separate rows in \texttt{forming\_limits.csv}:

\begin{enumerate}
  \item \textbf{Fracture (HC criterion).} The failure frame is the last output frame before the first element deletion, detected by a drop in \texttt{STATUS} below 0.5. The search is restricted to the \textit{dome zone}: elements whose undeformed centroid lies within $R_\mathrm{dome}$ of the punch axis, set to 15\,\% of the punch diameter per ISO~12004-2~\cite{ISO120042}. If the first deletion occurs outside this zone the run is flagged as a \textit{base fracture} and excluded from the FLC. The critical element is the one with maximum SDV1 (EQPS) in the dome zone at the pre-failure frame; its principal strains are computed analytically from the LE tensor eigenvalues.

  \item \textbf{Volk-Hora time-dependent criterion~\cite{VolkHora2011}.} Necking onset is identified from the thinning-rate history $\dot{\varepsilon}_\mathrm{thin}(t) = \dot{\varepsilon}_1 + \dot{\varepsilon}_2$ at the critical element. The signal is doubly smoothed and split at its inflection into a \textit{stable} phase (low, approximately linear increase) and an \textit{unstable} phase (rapid acceleration). A linear function is fitted to each phase; the intersection of the two lines is taken as the necking onset time. This criterion is purely time-dependent and does not rely on spatial strain gradients, making it directly applicable to FE history output.

  \item \textbf{SDV6 damage criterion.} The dome-zone maximum damage variable $D(t)$ (SDV6 from the HC VUMAT) is monitored frame by frame. Necking onset is taken as the inflection of this curve: $\operatorname{argmax}\,\ddot{D}(t)$. This criterion is disabled if SDV6 is absent from the ODB.

  \item \textbf{Min--Stoughton surface-curvature criterion~\cite{Min2017}.} The theoretical formulation is presented in Section~\ref{chap:theory}. In the numerical implementation, nodes on the outer surface of the sheet (opposite to the punch-contact interface) within the dome zone are read from the nodal displacement field \texttt{U} at each output frame. The default SAC value is $5\times10^{-4}$\,mm$^{-1}$, following the recommendation for Nakazima tests in~\cite{Min2017}. The necking condition must hold for eight consecutive frames. The method returns N/A if fewer than three dome-zone nodes are available or if \texttt{U} is absent from the ODB.
\end{enumerate}

All four limit points are overlaid on the FLC diagram produced by \texttt{plot\_flc.py}, allowing a direct comparison across criteria.

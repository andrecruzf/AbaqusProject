\chapter{Automated Numerical Framework}\label{chap:numerical_model}

\section{Framework Overview}

To complement the experimental campaign presented in
Chapter~\ref{chap:experimental_campaign}, a numerical simulation framework was
developed in \software{Abaqus/Explicit}~\cite{Abaqus2023}. Its purpose is to create, run, and
post-process the specimen and punch configurations considered in Task~I in a
reproducible way. The framework is not written for one single model, but for
repeated simulation campaigns in which the test type, geometry, mesh density,
material orientation, loading, and post-processing settings can be changed from
a common interface.

The main design goal was automation. Starting from a central configuration
file, the pipeline builds the finite element model, writes the
\software{Abaqus} input deck, submits the simulation, extracts the relevant
quantities from the output database, and stores the processed results in a
common format. This makes it possible to compare Nakazima, Marciniak, and
Punch-in-Punch simulations using the same numerical and post-processing
workflow.

Special attention was paid to the mesh. Since the numerical results should be
compared across different specimen and punch configurations, the element size
must be controlled systematically. The framework therefore includes
user-defined mesh-size modification routines, which allow mesh-refinement
studies to be generated automatically instead of manually rebuilding each
model.

\section{Framework Architecture}
\subsection{Central Configuration}

The framework is controlled through a central configuration file, which acts as
the primary control point of the numerical model. It defines the selected test
configuration, specimen dimensions, punch setup, mesh controls, material
orientation, contact parameters, loading conditions, solver settings, and
post-processing options. Parameters that are expected to change between
campaigns are exposed there, while the implementation of the model-building
steps remains fixed.

This separation reduces the risk of introducing unintended differences between
simulation cases. For example, a change in sheet thickness, punch diameter, or
mesh refinement factor does not require editing the \software{Abaqus} model
manually. The complete list of available configuration groups is given in
Appendix~\ref{app:configuration_parameters}.

In addition to editing this configuration directly, the framework provides a
graphical interface, built with \software{Streamlit}, that exposes the same
parameters through interactive controls and submits the selected case to the
cluster. It is an operational prototype that drives the same underlying pipeline
as the configuration file, so a case prepared in the interface is equivalent to
one configured by hand. Its layout and views are described in
Appendix~\ref{app:interface}.

\subsection{Automated Workflow}

The model generation is organised as a sequence of \software{Python} modules.
The main script first reads the configuration and then creates the specimen,
tools, assembly, material definition, analysis step, contact interactions,
boundary conditions, output requests, and job definition. Each simulation
therefore passes through the same sequence of operations, independent of the
selected test type.

After the model has been generated, the input file and the user material
subroutine are placed in the simulation directory. Once the
\software{Abaqus/Explicit} job has finished, the same post-processing script
reads the output database (ODB) and writes the force--displacement data, energy
histories, strain paths, and forming-limit points. The resulting file structure
is kept identical for all test configurations so that the results can be
aggregated without additional manual work.

\subsection{Integration with the ETH Euler Cluster}

The simulations are executed on the ETH Euler cluster. The local project files
are copied to the cluster. The solver job is then submitted through
\software{SLURM}, and the ODB post-processing is performed after the analysis
has completed.

Only the compact result files, figures, and movies are copied back to the
project directory. The large ODB files remain in scratch storage because of the
Euler storage policy for scratch directories.

\section{Automated Model Generation}

\subsection{Test Configurations}

Three test configurations are supported. The Nakazima model represents the
standard hemispherical-punch test and is used as the main reference
configuration. The Marciniak model uses a flat punch and provides a second
forming setup with a different strain-path character. The Punch-in-Punch model
contains an outer and an inner punch and is used to study a two-stage forming
process.

All three configurations are generated by the same framework. Differences such
as the number of punches, tool geometry, contact pairs, and loading sequence
are selected through the configuration file. 

\subsection{Geometry, Contact and Boundary Conditions}

To reduce the computational cost, only one quarter of the specimen is
modelled. Symmetry boundary conditions are applied on the two cut planes,
while all tooling components are represented as analytical rigid bodies. The
forming motion is prescribed through the punch reference point, whereas the die
and blank holder remain fixed. The outer blank edge is constrained to
represent the clamping action of the experimental setup.

Tool--blank interactions are modelled using hard normal contact with Coulomb
friction. The same contact formulation is employed for the Nakazima and
Marciniak configurations, while the Punch-in-Punch model activates the
additional contact interactions associated with the second punch. Consequently,
the overall modelling strategy remains identical across the three test
configurations, with only the geometry and loading sequence being adapted.

\subsection{Parameterised Mesh Generation}
\label{sec:mesh_generation}

The deformable sheet is discretised using eight-node linear reduced-integration
hexahedral elements (C3D8R). A solid formulation is adopted because the
constitutive model accounts for through-thickness deformation, damage evolution,
and element deletion.

A central requirement of the framework is that the element size is controlled in
a reproducible, geometry-independent way, so that simulations of different
specimen widths and punch configurations can be compared without the mesh
acting as an uncontrolled variable. Rather than meshing each model by hand, the
specimen is partitioned into a fixed set of concentric sections that establish a common
meshing topology for every geometry, shown in Figure~\ref{fig:bm_mesh_zones} for
the two specimen families. The sections run from a fine zone at the pole, where
the strain gradients are highest, outward to a coarser zone at the clamped
flange. Because the discretisation is produced entirely at the meshing stage and
is independent of the solver, any mesh can be generated and inspected at
low cost, without running a forming simulation.

\subsubsection{Concentric Sections}

Each section is assigned a target element size, and the specimen edges within it
are seeded to reproduce that size. The target size increases from the pole
towards the flange, following the decreasing strain gradient: the central zone
is the finest and the flange zone the coarsest, with two intermediate sections in
between (Table~\ref{tab:mesh_zones}). Two properties follow from this
construction. First, because the same sectioning and the same target sizes are
applied to every geometry, the element size at a corresponding location is
identical across all specimen widths and punch diameters; the specimen width only
changes how far the outer sections extend. Second, the central zone keeps a
constant fine resolution, so the region where fracture initiates is always
resolved consistently. Through the thickness, a fixed number of element layers is
used, which keeps the through-thickness resolution constant as well.

\subsubsection{Global Refinement}

For routine use and for mesh-convergence studies, the whole mesh is refined or
coarsened with a single global refinement factor that multiplies all section
sizes by the same amount, leaving the sectioning unchanged. This makes a
convergence study straightforward: the factor is stepped through a range and the
corresponding meshes are produced automatically, without remeshing any model by
hand. Figure~\ref{fig:mesh_mr_sweep} shows the \texttt{W100} specimen at three increasing
values of the factor; the sectioning is preserved and every section coarsens by
the same proportion.

\subsubsection{Independent Section Sizing}

Beyond uniform refinement, the target size of each section can be chosen
independently. This makes the mesh grading adaptable: the rate at which the
elements coarsen from the fine pole towards the flange can be tuned to
concentrate elements where they are most needed. As an example,
Figure~\ref{fig:mesh_growth} shows three meshes that share the same fine central
size but coarsen towards the flange at increasingly steep rates. A gentle grading
keeps a fine mesh across the whole dome at a higher element count, whereas a
steep grading concentrates the elements near the pole and reduces the overall
model size at the expense of resolution further out. These gradings are not
separate settings but particular choices of the per-section sizes, which
illustrates the flexibility of the sectioned approach.

The section boundaries and the per-section target sizes can be set either through
the pipeline web interface or directly in its configuration, so that a mesh can
be defined interactively or reproduced in a scripted study. The global refinement
factor and the gradings shown above are recovered as particular choices within
this same set of controls.

\section{Numerical Formulation}

\subsection{Material Model}

The sheet material is described through a user material subroutine (VUMAT). The
anisotropic plasticity model uses a Hill'48 yield function with a non-associated
flow rule, hardening follows a mixed Swift--Voce law, and fracture initiation is
described by the Hosford--Coulomb model.

The 46 material constants were taken from an existing calibration of AA5182, a
comparable \mbox{5xxx-series} aluminium alloy, since the AA5754 batch of the
campaign had not yet been characterised. They are used here as a surrogate, so
the numerical results serve to verify the framework rather than to predict the
AA5754 forming limits quantitatively.

The material orientation is defined through a local material coordinate system,
whose rolling direction can be specified in the master configuration. This
allows rolling- and transverse-direction simulations to be performed using the
same numerical model without modifying the underlying implementation.

Material degradation and fracture are represented through the internal damage
variables of the VUMAT, which trigger element deletion upon failure. Besides
representing crack initiation, the resulting deletion pattern is used during
post-processing to identify the fracture location and distinguish valid
dome-centred fractures from failures occurring outside the evaluation region.

\subsection{Quasi-Static Solution Strategy}

Although the experimental forming tests are quasi-static, the numerical
simulations are performed using \software{Abaqus/Explicit}. Maintaining a
quasi-static response therefore requires limiting the inertial effects
introduced by the explicit solution procedure while keeping the computational
cost within reasonable limits.

The numerical behaviour is governed by three coupled quantities: the punch
velocity, the mesh discretisation, and the applied mass scaling. A finer mesh
reduces the stable time increment, increasing the computational cost, whereas a
higher punch velocity or more aggressive mass scaling improves computational
efficiency at the expense of increased inertial effects. To reduce this coupling
to a tractable study, the punch velocity is fixed at
\SI{5}{\milli\meter\per\second}, using the previous numerical setup of
Sen~\cite{Sen2025} as a starting point rather than as a validation of
quasi-staticity. This value reflects a compromise between physical fidelity and
computational cost. In the experiment the punch advances at roughly
\SI{1}{\milli\meter\per\second}, and a typical test requires a punch travel on
the order of \SI{30}{\milli\meter} before fracture, so the physical forming event
lasts on the order of \SI{30}{\second}. Because \software{Abaqus/Explicit}
advances the solution at the stable time increment, reproducing this duration
at the true forming speed would require an excessive number of increments and a
prohibitive run time. Increasing the punch velocity shortens the simulated
process time in proportion and therefore reduces the cost, at the price of
larger inertial effects. At \SI{5}{\milli\meter\per\second} the simulated
process is reduced to about \SI{6}{\second}, corresponding to a factor-five
reduction in process time. Fixing this value removes one degree of freedom in
the explicit setup, so the scalar sensitivity study can focus on the two
remaining numerical controls: mesh density and mass scaling. Whether the
resulting simulations are sufficiently quasi-static is not assumed from the
punch speed; it is checked from the energy histories for each run.

To verify the validity of each simulation, the kinetic and internal energy
histories are extracted automatically during post-processing. The ratio of
kinetic to internal energy ($\mathrm{ALLKE}/\mathrm{ALLIE}$) is then evaluated
to quantify the influence of inertia. Together with the mesh and mass-scaling
sensitivity studies presented in Chapter~\ref{chap:results}, this provides the
basis for selecting numerical parameters that remain representative of the
physical quasi-static experiment.

\section{Automated Post-Processing and Forming-Limit Extraction}

Following each simulation, the output database (ODB) is processed
automatically through a common post-processing pipeline. The extracted
quantities serve two complementary purposes: validating the numerical
simulation and generating the data required for forming-limit
identification.

To assess the quality and consistency of the simulation, the pipeline extracts
the punch force--displacement response, the kinetic and internal energy
histories, and a series of diagnostic visualisations, including section and
isometric view animations together with representative mesh-topology snapshots.
These outputs allow the quasi-static assumption, deformation evolution, and
overall simulation behaviour to be verified without manual inspection of the
ODB.

For forming-limit identification, element-based quantities are extracted
throughout the simulation, including strain histories, damage variables, and
element status information. These data are used to detect crack initiation,
identify the fracture location, and extract the critical strain state from the
evaluation region. When requested, the same dataset is further processed to
evaluate necking indicators based on the Volk--Hora methodology and on the
damage evolution predicted by the constitutive model.

This automated post-processing stage converts the raw finite element results
into a standardised set of numerical outputs that mirrors the experimental
evaluation procedure. Consequently, both numerical and experimental forming
limits can be stored in a common format, enabling a direct comparison in
Chapter~\ref{chap:results} once validated numerical campaigns are available.

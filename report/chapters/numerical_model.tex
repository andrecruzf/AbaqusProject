\chapter{Automated Numerical Framework}\label{chap:numerical_model}

\section{Framework Overview}

To complement the experimental campaign presented in
Chapter~\ref{chap:experimental_campaign}, a fully automated finite element
framework was developed in Abaqus/Explicit for the numerical identification of
forming limits. The framework is configuration-driven and supports the complete
simulation workflow, from finite element model generation to automated
post-processing and forming-limit extraction, without requiring manual
interaction with Abaqus/CAE.

A single \emph{Master} configuration file acts as the central interface of the
framework. It defines the complete simulation setup, including the test
configuration, specimen geometry, mesh parameters, material model, boundary
conditions, solver settings, post-processing options, and computational
resources requested on the ETH Euler cluster. Consequently, complete simulation
campaigns and parameter studies can be reproduced by modifying only the
configuration file, while the underlying implementation remains unchanged.

The framework has been designed around three principles:

\begin{itemize}
    \item \textbf{Unified model generation.} The same implementation supports
    Nakazima, Marciniak, and Punch-in-Punch simulations. Differences between
    the test types are handled through configuration, ensuring a common modelling and post-processing workflow.

    \item \textbf{Parameterized model construction.} Geometry generation, mesh
    generation, material assignment, loading, contact, and output requests are
    created automatically from the selected configuration. In particular, the
    parameterized spider-web meshing strategy allows systematic mesh refinement
    while preserving a consistent mesh topology across different specimen
    geometries.

    \item \textbf{End-to-end automation.} The framework automatically generates
the Abaqus input deck, executes the simulation on the ETH Euler cluster,
extracts the quantities required for model validation and forming-limit
identification from the output database (ODB), and produces the corresponding
processed datasets and diagnostic plots..
\end{itemize}

The remainder of this chapter follows the execution of the framework. First,
the overall pipeline architecture and its integration with the ETH Euler
cluster are presented. The automated generation of the finite element models
for the three test configurations is then described, followed by the numerical
formulation, mesh generation strategy, and quasi-static verification. Finally,
the automated post-processing and forming-limit extraction procedures are
introduced.

\section{Framework Architecture}
\subsection{Master Configuration}

The framework is controlled through a single \emph{Master} configuration file,
which serves as the primary user interface to the numerical framework. All
parameters expected to vary between simulation campaigns are exposed through
this file, while implementation-specific definitions, such as the rigid tool
models and their interaction formulations, remain fixed within the framework.

The Master configuration gathers the user-defined parameters that typically vary
during simulation campaigns, such as the test configuration, loading,
discretization, and solver settings. Additional options are activated only when
required by a specific test configuration, allowing all studies to be conducted
through a common interface.

This separation between user-defined simulation parameters and implementation
details enables complete simulation campaigns and parameter studies to be
conducted by modifying a single configuration file, while preserving a
consistent numerical implementation and minimizing the risk of unintended model
modifications. The complete list of available configuration parameters is given
in Appendix~\ref{app:configuration_parameters}.
